### 核心概念解析

本节将深入解析 PyBroker 中的一些核心设计理念和关键组件，帮助您更好地理解和使用该框架。

#### **仓位管理: `PosSizeContext` 与 `pos_size_handler`**

在 `pybroker` 中，仓位管理是一个核心功能，它通过 `PosSizeContext` 和 `pos_size_handler` 的协同工作来实现。这种设计将"交易信号的生成"与"仓位大小的决策"清晰地分离开来，提供了极大的灵活性。

1.  **`PosSizeContext` (仓位大小上下文)**
    -   **是什么**：一个包含决策仓位大小时所需全部信息的"数据快照"或上下文对象。
    -   **作用**：
        -   **汇集信号**：当策略为多个股票生成买卖信号后，`PosSizeContext` 会将这些信号 (`ExecSignal`) 全部收集起来。
        -   **提供全局信息**：您可以从中获取投资组合的当前现金、所有持仓、历史交易、指标数据等全局信息。
        -   **提供修改接口**：通过 `ctx.set_shares()` 方法，您可以在处理器中为每个信号动态设置最终的交易股数。

2.  **`pos_size_handler` (仓位大小处理器)**
    -   **是什么**：一个由用户自定义的、用于实现具体仓位管理逻辑的函数。您通过 `Strategy.set_pos_size_handler()` 将其注册到策略中。
    -   **作用**：接收 `PosSizeContext` 对象，并根据您的自定义逻辑（如风险平价、波动率加权等）来计算每个交易信号应分配的最终股数。

3.  **协同工作流程与用途**
    -   **解耦设计**：策略执行函数只负责在"正确的时间"对"正确的股票"发出"买/卖"的初步意图；而 `pos_size_handler` 则从全局视角，负责根据所有信号来统一进行资金分配和风险管理。
    -   **执行时机**：`handler` 在策略生成所有初步信号之后、但在真正下单之前被调用。
    -   **强大用途**：这种机制使得实现高级资金管理策略成为可能，例如：
        -   基于波动率倒数加权，为低风险股票分配更多资金。
        -   实现风险平价（Risk Parity）模型。
        -   基于信号得分进行排名加权。
        -   确保所有交易的总风险敞口在预设范围内。

通过理解并善用这一机制，您可以构建出更加复杂和稳健的量化交易策略。

#### **回测引擎工作流程**

`pybroker` 的回测引擎 (`Strategy.walkforward`) 经过精心设计，将复杂的回测过程分解为四个清晰的阶段，确保了数据的准确处理和模拟的真实性。

1.  **阶段一：数据准备与预处理**
    *   **目标**：为回测准备所有必需的数据。
    *   **流程**：
        1.  **获取原始数据**：从指定的数据源（如 `Alpaca`）拉取原始OHLCV数据。
        2.  **数据过滤**：根据时间段（`between_time`）、交易日（`days`）等条件筛选K线。
        3.  **指标计算**：分析所有策略和模型，**一次性、并行地**计算所需的全部技术指标，并进行缓存。

2.  **阶段二：模型训练与滑动窗口**
    *   **目标**：使用历史数据训练模型，并以滚动方式向前推进回测窗口。
    *   **流程**：
        1.  **划分窗口**：将整个数据集划分为多个"训练集"和"测试集"对（即Walk-forward窗口）。
        2.  **模型训练**：在每个窗口的**训练集**上训练所有机器学习模型，确保模型仅使用过去的数据。
        3.  **执行回测**：在对应的**测试集**上运行核心的交易模拟。

3.  **阶段三：核心模拟循环**
    *   **目标**：逐根K线模拟真实的交易行为。
    *   **流程**（在每个交易日循环）：
        1.  **更新上下文**：更新 `ExecContext`，为策略逻辑准备好当前K线的数据。
        2.  **仓位决策**：调用 `pos_size_handler`（如果已设置），从全局视角决定最终的交易股数。
        3.  **检查止损**：检查并执行所有被当前K线价格触发的止损/止盈单。
        4.  **执行订单**：处理所有**计划在今天执行**的买卖订单，更新投资组合状态（现金、持仓等）。
        5.  **记录快照**：记录当前K线收盘后投资组合的权益、市值等状态。
        6.  **执行策略**：调用用户定义的策略函数 `fn(ctx)`，产生新的**交易意图**。
        7.  **调度新单**：将新的交易意图根据延迟（`buy_delay`/`sell_delay`）安排到未来的执行计划中。

4.  **阶段四：结果汇总与评估**
    *   **目标**：将模拟过程中的所有数据整理成报告。
    *   **流程**：
        1.  **数据转换**：将记录的交易、订单、投资组合历史等原始数据转换为 `pandas.DataFrame`。
        2.  **指标评估**：计算夏普比率、最大回撤、索提诺比率等一系列性能评估指标。
        3.  **打包返回**：将所有结果打包成一个 `TestResult` 对象返回，方便用户进行分析。

#### **滑点模型: `SlippageModel`**

为了让回测结果更贴近真实交易，`pybroker` 引入了滑点模型（`SlippageModel`）来模拟交易执行中的不确定性。

1.  **什么是滑点 (Slippage)**
    -   滑点是指在真实交易中，**预期的成交价格**与**实际的成交价格**之间的差异。这种差异通常由市场冲击成本（大额订单影响价格）、网络延迟或买卖价差引起。
    -   忽略滑点会导致回测结果过于乐观。

2.  **`SlippageModel` 的作用与工作原理**
    -   **作用**：在回测过程中模拟滑点，从而计入这项重要的交易成本。
    -   **如何使用**：
        1.  创建一个滑点模型实例，例如内置的 `RandomSlippageModel`。
        2.  通过 `strategy.set_slippage_model(...)` 将其应用到策略中。
    -   **工作流程**：
        -   在回测的核心循环中，当您的策略产生买卖意图后，框架会调用 `SlippageModel` 的 `apply_slippage` 方法。
        -   该方法会修改原始的交易意图。例如，`RandomSlippageModel` 会**随机减少您最终成交的股数**，以此模拟因价格向不利方向滑动，导致相同资金购买力下降的情况。
        -   通过这种方式，滑点的影响被量化并反映在最终的交易成本和策略表现中。

#### **上下文 (Context) 与作用域 (Scope) 的设计理念**

`pybroker` 的核心架构由"上下文"和"作用域"两个关键概念驱动，它们共同构建了一个高效、清晰且易于扩展的回测环境。

1.  **上下文 (`context.py`) - 提供给用户的"操作台"**
    *   **用途**：`Context` 对象是您在编写策略时进行交互的主要接口。它将特定时间点的所有相关数据和可执行操作打包，传递给您的策略函数，让您能方便地读取数据和表达交易意图。
    -   **核心实现**:
        -   **`ExecContext` (执行上下文)**：这是最常用的上下文（`fn(ctx)`中的`ctx`）。它归属于**单个股票在单个时间点**的策略逻辑，允许您读取该股票的数据（如`ctx.close`）并设置交易意图（如`ctx.buy_shares = 100`）。
        -   **`PosSizeContext` (仓位大小上下文)**：这是一个更高级的上下文，归属于**投资组合层面**的仓位管理逻辑 (`pos_size_handler`)。它允许您访问当前所有的买卖信号，并从全局视角统一分配资金、确定最终的交易股数。

2.  **作用域 (`scope.py`) - 幕后的"数据总线与缓存系统"**
    *   **用途**：`Scope` 对象负责在后台高效地管理、缓存和分发回测所需的所有数据。您通常不直接使用它，但它是保证回测性能的关键。
    *   **设计原因**：
        -   **性能与缓存**：回测涉及大量重复的数据查询。`Scope` 将数据（如某个股票的完整收盘价序列）在首次访问时加载到内存并缓存。后续的访问将直接从这个高效缓存中进行，极大地提升了回测速度。
        -   **关注点分离**：`Scope` 将"如何管理数据"的逻辑与 `Context` 中"提供什么接口给用户"的逻辑分离开来。这使得整个框架代码清晰、职责单一、易于维护和扩展。

3.  **二者如何协同工作**
    *   回测引擎创建各种 `Scope` 对象来管理数据。
    *   在模拟循环的每个步骤中，引擎会创建一个 `Context` 对象（如`ExecContext`）。
    *   引擎将 `Scope` 对象作为依赖"注入"到 `Context` 对象中。
    *   最后，这个准备就绪的 `Context` 被传递给您的策略函数。当您调用 `ctx.indicator(...)` 时，`Context` 内部会向其持有的 `IndicatorScope` 请求数据。

通过这种"前台（Context）"与"后台（Scope）"分离的设计，`pybroker` 兼顾了用户接口的简洁性和底层数据处理的高效性。

#### **模型集成: `ModelSource`**

`pybroker` 提供了一套强大的机制，可以将机器学习模型（如 `scikit-learn`, `PyTorch` 等）优雅地整合到 `walk-forward` 滚动回测流程中，确保了模型的时效性并有效避免了前视偏差。

1.  **核心理念：分离"配方"与"实例"**
    -   `pybroker` 将模型的"定义/配方" (`ModelSource`) 与"训练好的实例" (`TrainedModel`) 分离开来。你只需要提供配方，框架会负责在正确的时间为你烹饪（训练）。

2.  **关键组件**
    -   **`ModelSource` (模型源)**: 这是一个模型的"配方"。通过 `pybroker.model()` 创建，您需要为其指定：
        -   `indicators`: 训练该模型需要用到的技术指标列表。框架会自动计算这些指标并将其作为模型的输入特征。
        -   `train_fn`: 您自定义的**训练函数**。这是核心，框架将在每个回测窗口的训练集上调用此函数。
    -   **`TrainedModel` (已训练模型)**: 这是您的 `train_fn` 函数需要返回的对象。它是一个容器，内部打包了**实际训练好的模型对象**（例如一个 `RandomForestClassifier` 实例）。

3.  **工作流程 (Walk-Forward 模式下)**
    1.  **注册配方**：策略初始化时，创建并注册 `ModelSource`。
    2.  **进入训练窗口**：回测开始，框架划分出第一个训练集。
    3.  **调用训练**：框架准备好训练数据（包含您指定的指标），并调用您的 `train_fn`。
    4.  **返回实例**：您的 `train_fn` 函数执行训练，并返回一个包含训练好模型的 `TrainedModel` 对象。
    5.  **缓存实例**：框架将这个 `TrainedModel` 缓存起来，专门用于接下来的测试窗口。
    6.  **进入测试窗口**：回测进入测试集，在每一根K线上，您可以通过 `ctx.preds('your_model_name')` 来获取预测结果。框架会自动使用刚才缓存的模型进行预测。
    7.  **滚动前进**：当进入下一个 `walk-forward` 窗口时，上述流程会重复，从而实现模型的周期性再训练。

通过这种方式，`pybroker` 自动化了模型训练的整个生命周期管理，让您可以专注于模型本身的逻辑，而无需担心数据泄漏或复杂的滚动训练实现。

#### **指标系统: `Indicator`**

`pybroker` 的指标系统为策略提供了高性能、易于使用的技术指标支持。其核心设计理念是 **"声明式、预计算、全向量化"**，旨在将复杂的计算过程从策略逻辑中剥离，以实现极致的性能。

1.  **核心理念：一次声明，全量计算**
    -   与在每根K线上迭代计算不同，您需要在策略开始前**一次性声明**所有需要用到的指标 `Indicator` 对象。
    -   框架会在回测开始前，收集所有声明，并对每个股票的完整历史数据进行**一次性的、完全向量化的计算**（基于 `vectorbt`），然后将结果缓存备用。

2.  **工作流程**
    1.  **声明配方**：创建 `Indicator` 实例作为指标的"配方"，例如 `sma20 = pybroker.talib.sma(20)`。
    2.  **注册指标**：通过 `strategy.add_indicator()` 或在 `ModelSource` 中指定，将指标配方注册到策略中。
    3.  **向量化计算**：在回测的数据准备阶段，框架会调用 `vectorbt` 对每个股票的完整价格序列进行批量计算，生成完整的指标结果序列。
    4.  **缓存与访问**：计算结果被缓存到 `IndicatorScope` 中。在策略执行期间，当您调用 `ctx.indicator('sma20')` 时，它仅仅是从缓存中进行一次高速的数组查找，而**不涉及任何实时计算**。

3.  **设计优势**
    -   **极致性能**：向量化计算比传统的循环计算快几个数量级，这是 `pybroker` 高性能回测的基石。
    -   **简洁易用**：用户只需关注"需要什么指标"，而无需关心"如何计算"和"何时计算"，极大地简化了策略代码。
    -   **轻松扩展**：通过 `pybroker.indicator()` 函数，可以轻松地将自定义的计算逻辑包装成一个标准的、高性能的指标，与内置指标无异。
